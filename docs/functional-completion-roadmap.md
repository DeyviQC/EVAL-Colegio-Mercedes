# Functional Completion Roadmap

Date: 2026-10-08. This is a development status record, not approval to implement unresolved product decisions or evidence of institutional acceptance.

## Working local journeys

Real authentication and role boundaries; periods/catalog; enrollment creation/transfer/closure; assignment planning/activation/replacement/closure; bounded teacher/student accounts and password maintenance; course materials with protected files; activity publication/closure; student deliveries and retained versions; original-teacher AD/A/B/C grading/corrections; classroom reports; academic notifications; role-bounded enrollment/assignment history.

## Suggested sequence

1. Refine current journeys: accurate loading/error/empty states, explicit recovery, discoverability, clear filters and paging, preserved original contexts. Responsive shell/touch controls, reduced motion and deferred material maintenance consultation are now verified locally. Validate actual school tablets and refine remaining complex journeys based on observed difficulty.
2. Teacher/student delivery original-context presentation is implemented and verified locally. Director discovery and separate historical-transfer browser acceptance remain pending.
3. Course-scoped Library/search is implemented and locally verified. A separate institutional collection, file-content extraction and indexing remain separately scoped; no browse-all permission is implied.
4. Material title/description editing and withdrawal/restoration now work with retained revisions and historical privacy. Private vice-principal observations now work through an original-teacher response and explicit review, with historical read-only access. Attachment replacement now retains original and prior files, respects historical student visibility and preserves observed/replied file context. Wider correction chains and physical purge remain separately scoped.
5. Specify report export and broader account/import maintenance. Determine required formats, authorized roles, retained identities and official-grade boundaries without replacing SIAGIE.
6. Move development storage to a durable location and prove backup/restore. Finish deployment/server choice, school LAN/WLAN/outage, concurrency/load and institutional acceptance.

## Important limits

The local schema and launchers provide actual application behavior, but Git does not contain private passwords, databases, uploads or a reproducible installed runtime for another computer. Teammates need the documented dependencies/local maintenance setup. Synthetic verification accounts are not institutional enrollment. Main-branch integration and remote publication are separate Git operations from development verification.
