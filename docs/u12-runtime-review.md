# U12 Local HTTPS Runtime Proposal

Date: 2026-10-07. Pending human technical review, not an approved architecture selection. Backend journeys now run in-process; a real listener remains missing. OpenSpec tasks 1.6/1.7 and 8.2 require established runtime/browser commands before acceptance.

Recommended next slice: install the matching Laravel framework/kernel/routing dependencies locally, preserving the current locked Illuminate release where compatible; use a development-only PHP loopback HTTP listener behind a Node built-in HTTPS loopback adapter. Bind both to 127.0.0.1, not school/public interfaces. Generate development TLS material outside Git, trust that CA only in the test client, and verify certificates rather than disable TLS verification. Exact proxy trust/origin handling must be test-proven with forged forwarding-header negatives; external headers must not select actor, authority or HTTPS trust. This is a development harness, not IIS/Apache selection or production deployment.

Authorization requested for this slice includes scoped dependency retrieval from HTTPS repo.packagist.org, api.github.com and codeload.github.com into the existing local runtime, no global install/lifecycle scripts; local start/stop of owned loopback test listeners, disposable test MySQL only; a full request lifecycle with existing cookies/CSRF and server-owned composition. Verify actual dependency compatibility before pinning, and stop for review if compatibility demands a different framework major or academic/authentication contract.

Use declared synthetic fixture labels only in the isolated test composition; institution profile/name mapping remains pending and production composition must fail closed without an authoritative binding. No account/profile schema or UI is proposed. This slice does not enable public activity/submission writers, change retry/replay, install browser tooling, open firewall rules, select institutional load thresholds or complete 8.2.

Advantages: tests the approved Laravel direction and actual HTTPS/session lifecycle using existing PHP/Node without choosing the institutional web server; scoped dependencies and listener ownership can be verified. Disadvantages: additional framework dependencies and a development TLS/proxy boundary; passing loopback integration cannot establish LAN availability, browser security behavior, performance or institutional operation. Impact: local runtime configuration/bootstrap/route adapter, isolated scripts and request tests, version/evidence records; domain specs unchanged, global gates stay open.

Alternative: approve a framework-free development listener over the existing component closure first. Advantage: smaller dependency footprint. Disadvantage: another runtime path needing later Laravel integration and duplicated lifecycle/security verification. Impact: temporary server adapter rather than full selected framework; not recommended.

Further separate reviews after a verified runtime handoff: browser/React tooling and accepted-prototype role UI; minimal public reference transport integration; authoritative institutional profile source; LAN client/network setup; institution-approved synthetic seed dimensions, workload and load/lock/error thresholds. Do not infer those decisions from runtime approval.
