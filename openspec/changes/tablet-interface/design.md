# Tablet Presentation Design

Use the existing React/TypeScript shell and repo-native CSS. System fonts, no remote assets, no additional dependencies. Preserve existing route/client/credential behavior. Tablet unknown hardware implies conservative effects rather than assuming a model or importing an animation framework.

Desktop sidebar uses 236 pixels; 700–1100 CSS pixel widths use a compact 188 pixel sidebar; below 700 use an explicit section toggle, active section label and all existing authorized destinations. Main content has min-width zero, wrapped labels and touch-sized controls. Course material and Library cards use one column at tablet widths. Keep the existing institutional EVAL name, accepted blue identity and school name, and make controls, input borders, feedback and keyboard focus consistent.

MaterialOptions is a native details disclosure. Mount existing maintenance only when opened, avoiding its existing per-card initial status request. Preserve shared client unknown/pending/review state across disclosure unmounting. Primary file actions and existing private-observation consultation remain available. Do not add data fetching on hover, preload every card's history, or move server authorization into presentation flags.

Animate only a short initial content entrance and press feedback using opacity/transform. Enable animation only for no-preference and disable all animation/transitions for reduced motion. No infinite effects, blur, video, custom font downloads or blanket will-change. Browser navigation and disclosure remain usable without motion.

Verify responsive layouts and touch targets through existing local pinned-certificate Chromium tools. Measure deferred maintenance request counts, external request count and one CPU-throttled navigation journey. Existing material mutation and file recovery browser verifiers must open disclosure explicitly. This is not physical tablet, Android compatibility, full accessibility or LAN/load certification.
