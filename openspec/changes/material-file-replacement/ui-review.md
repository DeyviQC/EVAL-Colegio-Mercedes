# Proposed File Replacement Screen Mapping

Use the accepted EVAL shell, Materials cards and existing maintenance panel. No separate demonstration application is proposed.

## Original teacher

Available material -> Replace file -> current filename/type/size and consulted revision -> New file input -> explanation that original and older files remain retained -> Confirm file replacement / Cancel. Disable replacement when authority/state is unavailable or a result remains uncertain. Successful replacement refreshes the material card and revision history.

View retained file versions -> original publication plus paged replacement rows, each with safe filename/type/size, Peru timestamp and protected Open/Download. Editing metadata, withdrawal and restoration remain separate controls.

## Student

The existing Open/Download actions resolve the student's authorized file. No replacement form or global version-history control. Historical file names shown in Materials and Library must match the bytes the student can download.

## Vice principal

Material supervision -> protected current and retained file consultation. A private observation shows Open observed file; its teacher response shows Open file referenced by response. These resolve immutable revision context, even after a later replacement. No file replacement control.

## Recovery

If confirmation is lost, display the existing unknown-outcome pattern, disable writes, offer matching current-status consultation and require explicit manual review. Keep the selected file from being submitted automatically. A stale conflict requests consultation of the new revision before a separately confirmed action.
